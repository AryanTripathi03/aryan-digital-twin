# Content Guide

## Evidence labels

- Source-verified: implemented in inspected public source
- Document-verified: present in an inspected public PDF/document
- User-confirmed: supplied by Aryan but not independently documented
- Requires confirmation: do not publish as fact
- Excluded: confidential, sensitive or unsafe to publish

## Projects

Every project needs purpose, status, context, implemented solution, architecture route, stack, evidence, limitations and repository link. A live link is optional and should be omitted if the service is unsafe or unavailable.

## Experience

Keep company work high-level. Do not add raw data, screenshots, credentials, customer details, internal technology claims or business outcomes without explicit approval.

## Skills

Add a skill only with a named project or experience source. Do not add percentages.

## Certificates

Prefer original public PDFs, normalized filenames, issuer, issue date, credential ID/verification URL when present, and an accessible title. Do not invent missing metadata.

## Digital Twin

Any new answer must be supported by visible content and contain at least one anchor citation. The Twin must not answer private-personal questions.
